# games-hub 站内文案包

- 站点：games-hub / 游戏中心
- 撰写：字有物（内容）· 交付对象：team-lead
- 版本：**v3.3 单轨版**（2026-10-18，取代 v1.0 / v2.0 / v3.0 / v3.1 / v3.2）
- 依据：`index.html`、`game.html`、`tools.html`、`media.html`、`guestbook.html`、`login.html`、`account.html`、`_worker.js` 逐行核对

> **本方案按「保持登录门禁」这一前提编写，不涉及搜索引擎收录。** 站内每一句文案服务的对象都是已经登录进来的人，衡量标准只有两条：知不知道点哪、卡住时知不知道怎么办。与收录相关的方案（关键词地图、结构化数据、canonical、内链策略、专区布局页）本轮不实施，也不在本文档中保留半成品，避免开发阶段出现两套口径。

## 1. 内容缺陷修复清单（P0，逐条可验收）

### 1.1 我的世界 4 页 head 里带着第三方英文辱骂文案

| 项 | 内容 |
|---|---|
| **现状原文** | `<meta property="og:description" content="this file is not a website, whoever uploaded it to this URL is a dumbass">`<br>同时还有 `<meta property="og:locale" content="en-US">`、`<meta property="og:title" content="EaglercraftX 1.8 WASM-GC Offline">`、`<meta name="keywords" content="eaglercraft, eaglercraftx, minecraft, 1.8, 1.8.8">` |
| **来源** | Eaglercraft 离线包自带的防盗用声明。原作者写这句话的场景是「这不是一个网站，你别把它当网页挂」——而这个站恰恰就是把它当网页挂上去的 |
| **修复后文案** | ① `og:locale` 改 `zh_CN`；② `keywords` 整行删除；③ `og:title` 用第 10 节的中文 title；④ `og:description` 用第 11 节统一模板，示例见 1.1 下方 |
| **涉及文件** | `minecraft.html`、`minecraft-1122.html`、`minecraft-125.html`、`minecraft-classic.html`（每份 `<head>` 第 3–10 行区间） |
| **验证方式** | ① `grep -ci dumbass` 这四个文件，结果必须为 0；② `grep -c "en-US"` 结果必须为 0；③ 打开页面源码确认 `og:locale` 为 `zh_CN` |

**1.1 修复后的 og:description（以我的世界 1.8.8 为例）**

```
我的世界 1.8.8 网页版：1.8 老版本，单人开世界，存档存在你自己浏览器里。约 15MB，第一次进要等十几秒。浏览器直接打开就能玩，不用下载。
```

> 说明一句技术事实，供你判断优先级：门禁在的情况下，站外抓取这个链接会先拿到 302、读到的是登录页的 head，所以游戏页的 og 卡片**大多数时候不会被真正读到**。真正的价值是在用户已登录、自己复制链接的场景，以及以后万一放开。**删除辱骂句本身没有争议**（三行一起清掉成本极低），替换成中文文案是顺手做的事。

### 1.3 两张 Flash 封面只有 72×72 像素

| 项 | 内容 |
|---|---|
| **现状** | `bh32.jpg` = 72×72、`bh33.jpg` = 72×72（读 JPEG SOF 段实测），而 250px 宽的卡片封面框约 155×155，等于放大 2.1 倍 |
| **后果** | 死神VS火影两款是首页最有辨识度的封面（唯一有真实美术的两张），现在被放大到糊，反而比占位图更难看 |
| **修复后文案** | 不需要文案，需要素材：重截 640×400（16:10）JPG，`bh32-cover.jpg` / `bh33-cover.jpg`，单张 ≤80KB；游戏名与版本号不要压在画面上（卡片本身有文字层） |
| **涉及文件** | 新增两张图 + `games.json` 与 `_worker.js` 里对应条目的 `icon` 字段 |
| **若本轮来不及** | 退回占位方案：用统一风格的矢量卡（深紫底 + 「死神VS火影 3.3」大字 + 格斗图标），**不要继续放大 72px 图**——糊图比占位图更伤 |
| **验证方式** | 在 250px 宽卡片上肉眼确认无锯齿；`identify`/属性查看确认尺寸 ≥640×400 |

### 2.3 三条红线

1. **不编游戏内容**：1.2.5 与 Classic 两个包无法从代码确认版本，文案只写体积、版本号、浏览器直接开，并统一加「兼容性以实际打开为准」；可玩性描述等实测再补（见 1.4 V1）。

3. **不写「正版」「官方」「数万款」**：站里 9 款，文件是第三方构建与镜像，用户点开 5 秒就能验证。

## 3. 首页结构文案

**诊断**：现在首页从「游戏中心」直接跳到筛选条 + 卡片网格，只有 3 个信息层；9 张卡片的副信息全是 `14.4 MB`。体积回答的是「要等多久」，回答不了「值不值得等」。所以结构上做三件事：**按系列分组**（我的世界归我的世界，别和扫雷挤在一格）、每卡一句人话、给新手一段必读提示。

> 已按最新裁决改为**纯分组结构，取消「全部 / Flash 怀旧 / H5」筛选 tab**。9 款天然分三组，一屏半就能扫完，分组比筛选少一次交互。

### 3.0 结构总览（从上到下 7 块）

|---|---|---|---|
| 1 | 一句话主张 + 数字条 | 3 秒内说清「有什么、要不要等」 | 新增 |
| 2 | 我的世界网页版（4 卡） | 需求最大的系列排第一 | 分组 |
| 3 | Flash 怀旧（2 卡） | 差异化卖点 + 加载预期 | 分组 |
| 4 | 随手就能玩（3 卡） | 给没耐心的人一个立刻能玩的 | 分组 |

  `先按 Ctrl+F5 强制刷新（浏览器会缓存旧文件）。还不行就换个浏览器，或者去留言板写清用的什么浏览器、是不是手机。`

## 5. 加载与等待文案

**这是本次最该重写的一块。** 现状只有三句：`正在读取游戏信息...` / `正在加载 Flash 游戏，请稍候...` / `正在加载 H5 游戏...`，外加一句「体积约 65.9MB，请耐心等待 1–3 分钟」。三个问题：

1. 20 秒内画面毫无变化，用户以为卡死；
2. 「1–3 分钟」是平均值，网慢的人等到 5 分钟就开始怀疑；
3. 没有出口——而且 `game.html` 有个兜底：12 秒后**无条件隐藏加载遮罩**，用户直接对着黑屏发呆。

### 5.1 阶段划分（按真实流程，不自己发明阶段）

| 阶段 | 真实发生的事 | 典型时长 | 触发条件 |
|---|---|---|---|
| S0 读配置 | 拉 `/api/games` 找到这条游戏 | <1 秒 | 进入播放页 |
| S1 下载 | 下载 SWF（经 Worker 中转）或 H5 单文件 | 3 秒–3 分钟 | 有大文件 |
| S2 初始化 | Flash：Ruffle 解析 SWF、启动 AVM；H5：解析并编译 WASM | 2–15 秒 | 下载完但无画面 |
| S3 就绪 | Ruffle 触发 `loadedmetadata` / iframe 出画面 | 1–2 秒 | — |

### 5.2 分阶段文案

**S0 · 读配置**
- 主：`正在准备…`
- 副：不显示
- 备注：只停留不到 1 秒。**超过 3 秒还停在这说明接口挂了**，直接跳第 6.2 节的「读取游戏信息失败」。

**S1 · 下载中（Flash，58.9 / 65.9MB）**
- 主：`正在下载游戏文件…`
- 副：`死神VS火影 3.3 约 66MB，第一次玩要下完整包`
- **有进度时**（Ruffle `progress` 事件或自己 `fetch` + `ReadableStream` 统计，二选一，可行性由前端确认）：主文案下加一行 `已下载 32% · 约 21MB`
- **拿不到进度时**：不显示百分比，走 5.4 的定时轮换

**S1 · 下载中（我的世界 15.1 / 20.1MB）**
- 主：`正在下载游戏文件…`
- 副：`我的世界 1.12.2 约 20MB。第一次打开要等一下，之后浏览器会缓存`

**S1 · 下载中（6MB / 3.6MB 的我的世界，以及三款小游戏）**
- 主：`正在加载…`
- 副：不显示。这两款体积小，说「要等」反而让人以为很慢；三款小游戏是纯页面，根本没有下载阶段。

**S2 · 初始化（Flash）**
- 主：`文件下完了，正在启动 Flash 模拟器…`
- 副：`这一步是在把画面准备好，通常几秒钟`
- 为什么这么写：用户看到进度满了却没画面，最容易以为失败。「文件下完了」专门用来安抚这个时刻。

**S2 · 初始化（我的世界）**
- 主：`文件下完了，正在加载游戏引擎…`
- 副：`第一次打开会久一点，之后就不用再等了`

**S3 · 即将就绪**
- 主：`马上就好…`
- 副：`如果一直停在这里，按住 Ctrl 再点刷新`

**S-慢 · 超过 30 秒仍在下载**（主动出现，不让人干等）
- 主：`下载比平时慢`
- 副：`可能是网络不太好。你可以继续等，也可以先去玩个不用加载的。`
- 按钮：`继续等` / `换个小游戏`（→ `/game2048`）

**S-超时 · 超过 120 秒仍无画面**
- 主：`还没加载完`
- 副：`这么大的文件卡住，通常是网络断了或者被拦了。刷新一下多半能好。`
- 按钮：`重试` / `回游戏中心`

### 5.3 首次 vs 二次（成本很低，收益明显）

用 `localStorage` 记 `ghub_seen_{游戏id}`：

- 第一次进来写：`第一次玩这款，要下完整包`
- 第二次起改写：`这次不用重新下载，应该很快`
- **第二次仍然很慢**：说明缓存没生效，副文案换成 `你这边好像没缓存成功，可能是无痕模式或缓存被清了`

### 5.4 进度不可知时的措辞（每 8–10 秒换一句）

**规则：不出现任何百分数、不出现「99%」、不把「请稍候」单独成句。**

| 时间 | 文案 |
|---|---|
| 0–10 秒 | `正在下载游戏文件…` |
| 10–25 秒 | `文件有点大，还在下…` |
| 25–50 秒 | `还在下载，不用管它，快好了…` |
| 50–90 秒 | `网速慢的话要一两分钟，别关页面…` |
| 90 秒+ | `有点久。要不要先玩个不用等的？` + 按钮 `换个小游戏` |

同时**始终显示一行**：`正在下载：约 66MB`。体积是确定信息，比假进度条更让人安心。

### 5.5 必须删掉的一段代码

```js
// game.html 现状：12 秒后无论成功与否都隐藏加载提示 → 用户对着黑屏发呆
setTimeout(() => { document.getElementById("loading").style.display = "none"; }, 12000);
```

改成：12 秒后**不隐藏提示，而是把副文案换成**「如果一直黑屏，按住 Ctrl 再点刷新」。黑屏 + 无提示是流失最快的一种状态；不改这行，前面 6 个阶段的文案全被它抹掉。

### 5.6 留言板列表加载态

- 加载中（现「加载中…」）：`正在加载留言…`
- 首次进入无数据：直接上骨架屏（3 行灰条），避免文字闪烁

### 6.5 接口错误码文案对照表

本轮接口扩展后前端要照这张表展示。**原则：不出现「请求」「参数」「频率」「额度」这类词，换成用户能对上号的说法。**

**契约对接（三条，前端照做，文案里不再留分支）**

1. 错误体是 `{error, code}`。`error` 直接显示（本表已把它写成可读中文），`code` 只用于分支与埋点、不显示给用户。
2. **3 个 AI 限流码（429）必返回 `resetAt`（epoch 毫秒）与 `window`（`hour` / `day`）**。前端用 `Math.max(0, resetAt - Date.now())` 自己算剩余分钟，填进文案的 `{剩余}`。`window` 决定走小时档还是当日档。
3. **每日上限 `{N}` 取契约常量，不是响应字段**；全站档（`global_quota_exceeded`）不带 `window`，所以不显示剩余时间。

#### A. AI 对话限流（3 个 429，只服务 `/api/ai/chat`）

**注意：这三个码跟留言板无关。**动词用「聊 / 问」，量词用「次」。

| 错误码 | 场景 | 主文案 | 说明（第二行） |
|---|---|---|---|
| `user_rate_limited` + `window=hour` | 同一账号这一小时对话次数超限 | `这一小时问得有点多` | `歇一会儿再聊，{剩余} 分钟后就能继续。` |
| `user_rate_limited` + `window=day` | 同一账号当天对话次数触顶 | `今天的对话次数用完了` | `每天最多 {N} 次，明天再来。` |
| `ip_rate_limited` | 同一网络出口对话次数过多 | `这个网络现在聊不了` | `宿舍、公司、公共 Wi-Fi 常常几十个人共用一个出口，别人问多了也会连累到你。换个网络，或者等 {剩余} 分钟。` |
| `global_quota_exceeded` | 全站当日对话总量触顶 | `今天全站能聊的次数满了` | `这是站长设的上限，防的是刷接口，跟你没关系。明天再来。` |

#### B. 留言板限流（`msg_rate_limited`，10 分钟内 5 条）

| 错误码 | 场景 | 主文案 | 说明（第二行） |
|---|---|---|---|
| `msg_rate_limited` | 同一用户 10 分钟内留言超 5 条 | `发得有点快` | `留言板 10 分钟内最多 5 条，过一会儿再发。要补充的话，把话攒在一条里写。` |

#### C. 其他错误码

| 错误码 | 场景 | 主文案 | 说明（第二行） |
|---|---|---|---|
| `admin_required` | 非管理员执行删除/管理操作 | `这个操作要管理员` | `普通账号只能发留言、聊 AI。删留言、改 AI 预设得用管理员账号登录。` |
| `username_taken` | 注册/改名撞名 | `这个用户名有人用了` | `换一个吧，加两个字或数字都行，比如名字后面带个 07。` |
| `msg_not_found` | 删除的留言已不存在 | `这条留言已经不在了` | `可能是刚被别人删掉，或者你打开的是旧页面。刷新看看。` |
| `preset_not_found` | 选中的 AI 预设刚被管理员删掉 | `这个预设模型刚被删掉了` | `刷新页面重新选一个。如果你是管理员，去 AI 预设管理看看还剩哪些。` |

  - 用户名 placeholder：`用户名（2–20 位，字母、数字、下划线或中文）`

> `/login` 与首页弹窗两处必须用**同一套文字**。现在两处各写一套，同一个错误两种说法。

### 7.3 「第一个注册的账号成为管理员」怎么改

它的真实含义：站内还没有任何账号时，注册者自动拿到管理员权限。**不适合当时刻挂着的提示**，因为它暗示"要抢"，对已有账号的站更是毫无意义。拆成两处：

1. **平时**（tab 下方常驻）：`没有账号？点「注册」，填个名字和密码就行，不用验证邮箱。`
2. **注册成功且确实是第一个账号**（一次性提示，刷新即消失）：
   - 标题 `你是这个站的第一个账号`
   - 说明 `已经拿到管理员权限：能删除留言板里的留言、管理 AI 预设。其他人注册就是普通账号。`
   - 按钮 `知道了，开始玩`
3. **普通注册成功**：`注册好了，直接用就行` + 自动跳首页（或 `next`）

## 9. 按钮与确认弹窗统一

现在混用符号与格式：`开始游戏 →`、`新窗口打开 ↗`、`⛶ 全屏`、`← 返回`、`登录 / 注册`、`重新加载`、`重试`。同一件事两种说法（`重新加载` 与 `重试`），箭头符号有的带有的不带。

### 9.1 四条规则

1. **按钮文字不带符号**：箭头、`↗`、`⛶`、`←` 交给图标实现。理由：复制粘贴会带符号，屏幕阅读器会把箭头读成噪音。
2. **动词开头，2–4 字**：`开玩` 而不是 `开始游戏 →`。
3. **一个动作只有一个词**：全站统一 `重试`，不再出现 `重新加载`。
4. **危险动作的按钮写动作名**，不写 `确定`；确认弹窗里的第二个按钮永远叫 `取消`。

## 12. 收尾

### 12.1 文案上的关键取舍

1. **体积降级、玩法升级**。体积回答「等多久」，玩法回答「值不值得等」。现在卡片只有前者，等于让用户凭文件大小决定玩什么。
2. **加载态从 1 句扩到 6 阶段**。不是变啰嗦，是把「黑屏 40 秒」变成「有 4 次反馈的等待」。大文件站流失最多的位置就在这里。
3. **主动写清三个限制**：手机玩不了扫雷和贪吃蛇、存档在浏览器本地会丢、大文件首次要等 1–3 分钟。承认限制会掉一点转化，但能省掉一半「怎么玩不了」的留言。
4. **「第一个注册成为管理员」从常驻改成一次性提示**。它是给站长的说明，不该挂在登录页让所有访客以为要抢注。
5. **删掉「数据存储在 Cloudflare KV（免费额度）」这类技术自述**。用户不需要知道后端是什么，他需要知道自己能在这干什么。
6. **错误文案不出现「请求」「参数」「频率」「额度」**。这几个词用户一个都对不上号，换成「问得有点多」「发得有点快」「到上限了」才对得上。另外 AI 限流说「聊 / 问」、留言限流说「发」，两套语气不能混。
7. **没实测过的游戏只写客观事实**。1.2.5、Classic、死神VS火影双人这三点都没人实测过，所以文案只保留体积、版本号、玩法类型，把可玩性与人数交给站长实测后再补（1.4）。少写一句卖点的损失，远小于用户点进去发现跟描述不一样。
8. **取消筛选 tab，改固定三分组**。9 款游戏分三组一屏半看完，筛选是给几十款游戏准备的交互；同时删掉重复分组名的快捷入口条——那不是信息密度，是噪音。
9. **页脚署名真名「落雪」并紧跟「个人小站，非商业用途」**。真名换信任，但必须先划清商业边界，否则后面会有人来谈合作或投诉授权。

### 12.2 三处已拍板的事（记录在案，别再改回去）

1. **1.2.5 与 Classic 先保守写**：只说体积、版本号、浏览器直接开，加一句「早期版本，兼容性以实际打开为准」。不写可玩性、不写"经典版本等你回忆"。**待站长实测后补充可玩性描述**（1.4 V1）。
2. **死神VS火影一律不提双人**：只写格斗玩法与选人开打。等实测确认支持 2P 再加回来（1.4 V2）。
