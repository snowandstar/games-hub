## 1. 设计基调判断：保留基调，重做表面系统

### 1.1 结论（一句话）

**保留深色紫蓝的基调，但把"玻璃"从内容层撤掉、把散落的硬编码收敛成 token、把背景从三段渐变压成一层。视觉方向不变，表面系统重做。**

不是"保留原样"，也不是"推翻重做"。区别在下面这张表里，改的 6 处都是可量化的：

| # | 现状 | 改成 | 为什么（证据） |
|---|---|---|---|
| 1 | `.card` 上 `background:rgba(255,255,255,.07)` + 卡片本身不模糊，但**背景 `background-attachment:fixed` 在 100% 设备上跑** | 拆成 `--surface-1/2` 两个显式 token，背景改写为固定定位伪元素（桌面端）+ 纯色（移动端） | `background-attachment:fixed` 在 iOS Safari / 低端安卓滚动时每帧重绘整屏渐变，这是当前掉帧第一位的原因（site-spec 6.10.5 已判定） |
| 2 | 9 张卡各自 `transition: transform` + `will-change: transform` | 移动端**彻底取消** hover 位移；桌面端保留 4px 上浮但去掉 `will-change` | `will-change` 会为 9 个元素各自开合成层，中低端机显存吃紧；而卡片位移在触屏上根本触发不到，纯属白付成本 |
| 3 | `--dim:#8a92b8` 当次要文字用，且卡片底色随背景渐变浮动 | `--text-muted:#9aa3c7` 固定值，且**把背景最亮档从 `#302b63` 压到 `#241f4d`** | 实测：`#8a92b8` 在卡片表面只有 **3.38:1**（当前 12px 小字全线不达标）；`#9aa3c7` 在现在的卡片上只有 4.15:1，**压暗背景后升到 5.17:1**。压背景是唯一能一劳永逸锁死对比度的做法 |
| 4 | 封面 `img{max-width:62%}` 对 SVG 图标和真人截图用同一条规则 | 拆 `.cover--icon` / `.cover--shot` 两种 | Flash 封面换成 640×400 截图后，62% 宽会缩成小图贴在渐变上，两边留大片背景色，是"实现走样"的高危点（见第 3.2 节） |
| 5 | `role="tablist"` 套在导航上、`<a role="listitem">` | 导航是 `<nav>` + `aria-current="page"`；卡片是 `<ul><li><a>` | 语义错误会让读屏把导航念成"选项卡 1/2/3"，且 `<a>` 上的 `listitem` 会让链接失去"链接"播报 |
| 6 | 登录页与首页弹窗各写一套输入框与按钮 | 同一套 `.field` / `.btn` 规格 | 现在两处字号差 0.5–1px、圆角差 1px、错误文案两套，是纯粹的视觉噪音 |

### 1.2 视觉方向（三个形容词 + 一个参照物）

**克制、清楚、有手感 —— 像 Linear 官网的深色模式。**

- **克制**：界面不抢戏。这站的全部价值是「找到游戏 → 点开 → 玩」，任何发光、渐变文字、呼吸动画都在跟游戏画面抢注意力。
- **清楚**：8 个区块必须一眼分得清边界。深底 + 满屏毛玻璃最大的问题是**把 9 张卡压成一片紫色**，分组就等于没分。
- **有手感**：`120ms` 的按下反馈、`44px` 的可点区域、`focus` 一定看得见。移动端主力，手指比鼠标更需要"我按到了"的确认。

为什么拿 Linear 而不是拿游戏站做参照：游戏站普遍靠高饱和撞色和动效制造兴奋，那套在**手机上打开、等 20 秒加载**的场景里只会放大焦躁。这站需要的是"工具站的可信感 + 一点点街机的暗调"，不需要"热闹"。

### 1.3 为什么不全盘重做（不换浅色）

三条硬理由，按权重排：

1. **游戏画面是黑的。** 4 个《我的世界》大包、2 个 Flash 播放器，画面底色都是深色。浅色外框 + 深色舞台 = 明显的"套壳感"，而且白底会在加载时先闪一下再变黑，视觉冲击比现在更差。
2. **深色是这类站的默认预期。** 用户是"深夜想玩两把"的熟人，不是来采购的。浅色版会让"打开就能玩"变成"打开像在填表"。
3. **全站重做=重写 15 个页面的 `<style>`。** 本案没有构建工具、没有视觉回归测试，全面重做的回归风险远大于收益。**改 token + 改表面层，改动集中在 3 个文件（首页/登录/播放页），其余页面靠"换 token 自动跟随"。**

### 1.4 为什么也不能原样保留

三条实测问题，任何一条单独存在都足以否掉"原样保留"：

1. **对比度不达标且不可控**：`--dim #8a92b8` 在卡片上 3.38:1。更麻烦的是它随背景渐变浮动，同一个 token 在不同滚动位置对比度不同——**这种变量是无法验收的**，必须先把背景锁定。
2. **性能**：`background-attachment:fixed` + 9 张卡的 `will-change` + 悬停 `translateY` 全部无差别给到移动端。目标用户手机打开、发链接给朋友，首屏就掉帧最伤。
3. **分组失效**：8 区块的 IA 已经冻结，但现有视觉只有"卡"这一种容器。区块 6（三条提示）和区块 7（站内其他）如果还用卡片，用户会分不清"哪个能点开玩"。

## 2. Design Token

### 2.1 颜色系统

**对比度基准**：本站背景是渐变，任何文字都可能落在不同亮度的底色上。所以我在计算时取**最坏情况**——背景最亮档 `#241f4d` 再叠一层 `--surface-1`（`rgba(255,255,255,.06)`）= **`#312c58`**。所有正文/次要文字的达标判定都以此为准；在实际页面更暗的位置只会更好。

| `--text-2` | `#c2c8e2` | 次要文字、说明段 | **7.75:1** | 9.18:1 | ✅ AAA |

**中性色阶（深色侧）**：`#0b0918` → `#141130` → `#191634` → `#241f4d` → `#312c58` → `#3a355f`（后两档由白色叠加得到，不单独出 token，避免出现第三套灰阶）。

**语义色的 soft / border 变体**：soft = 同色 `alpha .12–.14` 的底，border = 同色 `alpha .32–.34` 的 1px 描边。用于提示条、徽章，**不出文字**——文字一律用上面的实色。

**状态矩阵**（交互元素必须四态齐全，缺一态就是缺陷）：

| 角色 | 默认 | hover | active（按下） | disabled |
|---|---|---|---|---|
| 主按钮 | 底 `--accent` / 字 `--text-on-accent` | 底 `--accent-hover` | 底 `--accent-active`，`transform:scale(.99)` | 底 `--accent` + `opacity:.45`，`cursor:not-allowed`，无 hover 反馈 |
| 次按钮 | 底 `--surface-1` / 字 `--text-1` / 边 `--border` | 底 `--surface-2`，边 `--border-strong` | 底 `--surface-2` + 内阴影 `inset 0 1px 3px rgba(0,0,0,.4)` | `opacity:.45`，`cursor:not-allowed` |
| 危险按钮 | 底 `--danger-fill` / 字 `#fff` | 底 `--danger-fill-hover` | 同 hover + `scale(.99)` | `opacity:.45` |
| 文字按钮/链接 | 字 `--link` | 字 `--link-hover` + 下划线 | 字 `--accent` | 字 `--text-muted`，`text-decoration:none` |
| 卡片 | 底 `--surface-1` / 边 `--border` | 边 `--border-strong` + 阴影 `--sh-2`（**不提亮底色**，见下） | `transform:translateY(1px)` | — |

> **卡片 hover 不提亮底色的理由**：底提到 `--surface-2`（`#3a355f`）后，卡内 `--text-muted` 掉到 **4.55:1**，只剩 0.05 的余量，任何一点调色都会击穿 AA。用"加边框 + 加阴影"表达 hover，对比度就不受影响。

### 2.2 背景与表面（三层，不许再分层）

```
第 0 层  页面底      --bg-base #0b0918（移动端就是这一层，纯色，零成本）
第 1 层  渐变        桌面端 ::before 固定定位：linear-gradient(160deg,#0b0918,#241f4d 58%,#191634)
第 2 层  光晕        桌面端同层叠两个 radial（紫 .10 / 蓝 .07），移动端全部关闭
第 3 层  表面        --surface-1（卡片/面板）· --surface-2（hover/次级面板/输入框组）
第 4 层  浮层        --sheet #141130（抽屉、模态、Toast）· --scrim rgba(5,3,18,.72)
```

- `--surface-1 = rgba(255,255,255,.06)`、`--surface-2 = rgba(255,255,255,.10)`——**只有这两个透明度值**，不许出现 `.05 / .07 / .08 / .12` 等历史上散落的中间值。
- 输入框底用 `--field-bg = rgba(0,0,0,.35)`（不是白色叠加）：深色输入框比周围暗，眼睛才认得出"这里可以打字"。实测它对卡片面的对比是 1.26:1，配合 `--border-field`（3.83:1）足够识别。
- `--sheet` 是唯一不透明表面，只给浮层用。不透明 = 浮层后面不需要模糊也能分层，这是性能账。

### 2.3 字号阶梯（移动 / 桌面两套值）

字体栈（只用系统字体，零网络请求）：

```css
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
             "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", sans-serif;
--font-mono: ui-monospace, SFMono-Regular, "SF Mono", Consolas, "Liberation Mono", monospace;
```

`--font-mono` 只用于三个地方：体积数字、时间戳、进度百分比。数字一律 `font-variant-numeric: tabular-nums`（数字条上下对齐不跳）。

| 角色 | 移动 (<820) | 桌面 (≥820) | 行高 移动/桌面 | 字重 | 字距 | 用在哪 |
|---|---|---|---|---|---|---|
| `--fs-h1` | 26px | 36px | 1.25 / 1.20 | 700 | -0.01em | 首页 H1、登录页 H1、404 H1 |
| `--fs-h2` | 19px | 24px | 1.35 / 1.30 | 700 | 0 | 区块头（8 区块的第 3/4/5/6/7） |
| `--fs-h3` | 16px | 18px | 1.45 / 1.40 | 600 | 0 | 卡片标题（桌面 17px 见 3.2）、提示条小标题 |
| `--fs-body` | 15px | 16px | 1.75 / 1.75 | 400 | 0 | 正文、说明段、输入框 |
| `--fs-sm` | 13px | 14px | 1.70 / 1.70 | 400 | 0 | 次要说明、按钮文字（14px）、区块副标题 |
| `--fs-xs` | 12px | 12px | 1.60 / 1.60 | 400 | 0 | 体积、时间、页脚、卡片副文案 |
| `--fs-label` | 11px | 11px | 1.40 / 1.40 | 600 | 0.04em | 类型徽章、字段标签、侧栏分组标题 |
| `--fs-metric` | 20px | 24px | 1.20 / 1.20 | 700 | -0.01em | 数字条里的数字 |

规则：
- **中文行高不低于 1.6**，正文 1.75；标题 1.2–1.35。低于 1.5 的中文正文在手机上会"黏成一片"，不做。
- 移动端最小 12px，**不再出现 10.5px / 11.5px 这类半像素字号**（现有 `.tab .n` 用 10.5px，安卓上会被渲染成 10 或 11，不可控）。
- 单行文本最大宽度：正文 640px（`--prose`），区块副标题 560px。超过这个宽度中文行会太长，眼睛回扫困难。

### 2.5 圆角

| Token | 值 | 用途 |
|---|---|---|
| `--r-xs` | 6px | 徽章、标签、代码块 |
| `--r-sm` | 10px | 输入框、次按钮、导航项、小图标容器 |
| `--r-md` | 12px | 主按钮、Toast、提示条 |
| `--r-lg` | 16px | 游戏卡片、面板、骨架屏 |
| `--r-xl` | 20px | 模态框、登录卡片、抽屉顶部 |
| `--r-pill` | 999px | 快捷入口胶囊、计数徽章 |

嵌套规则：**外圆角 = 内圆角 + 内边距**，误差 ±2px。卡片 16px 内边距 14px 时，内部图标容器用 10px 而不是 16px，否则会出现"双层圆角打架"。

### 2.6 阴影与描边（深色下阴影很弱，靠描边分层）

| Token | 值 | 用途 |
|---|---|---|
| `--sh-1` | `0 1px 2px rgba(0,0,0,.32)` | 卡片静止、输入框 |
| `--sh-2` | `0 8px 24px rgba(0,0,0,.36)` | 卡片 hover、下拉 |
| `--sh-3` | `0 24px 64px rgba(0,0,0,.56)` | 模态框、抽屉 |
| `--ring-focus` | `0 0 0 3px rgba(165,180,252,.28)` | 聚焦光晕（叠在描边外） |

深色界面里"阴影=变黑"，纯黑阴影在 `#0b0918` 底上几乎看不见。所以**分层主要靠 `--border` 和表面亮度差**，阴影只用于浮层（`--sh-3`）和 hover 的轻微托起。不要在卡片静止态堆阴影——9 张卡的阴影会互相污染成一片灰雾。

### 2.7 模糊（只给 3 个地方）

| Token | 值 | 允许用在哪 |
|---|---|---|
| `--blur-chrome` | 12px | 桌面侧栏、移动顶栏 |
| `--blur-sheet` | 20px | 抽屉、模态框、Toast |

**明确禁止 `backdrop-filter` 的位置：游戏卡片、封面、列表项、页面背景、任何重复 ≥3 次出现的元素。** 理由见第 7 节。桌面侧栏本来就在最上层，模糊几乎看不出来，可以进一步降为 `none` 换成不透明 `--sheet`——这一条我给前端留了选项，默认关掉。

### 2.8 动效

| Token | 值 | 用途 |
|---|---|---|
| `--dur-1` | 120ms | 颜色/描边/焦点变化（"按下有反应"） |
| `--dur-2` | 200ms | 卡片 hover、展开收起 |
| `--dur-3` | 320ms | 抽屉、模态框进出 |
| `--ease-out` | `cubic-bezier(.2,.8,.2,1)` | 进入、hover（先快后慢，有减速手感） |
| `--ease-in-out` | `cubic-bezier(.4,0,.2,1)` | 位移、抽屉 |

- 过渡只写**具体属性**（`transition: background-color var(--dur-1), border-color var(--dur-1)`），不写 `transition: .15s` 全属性（现有代码就是 `.15s`，会把 `transform` 和 `box-shadow` 一起带上，滚动时反复触发）。
- 任何位移动画上的元素数量 **≤1**。整屏卡片一起上浮是"廉价感"的主要来源，也是掉帧来源。

### 2.9 层级（z-index 只用这 6 档）

| 值 | 用途 |
|---|---|
| 0 | 普通内容 |
| 10 | sticky 顶栏 / 侧栏 |
| 30 | 页内浮层（下拉、Toast 之外的小提示） |
| 50 | Toast |
| 80 | 模态框 + 遮罩 |
| 90 | 抽屉（全屏导航，压过一切） |

## 3. 组件规格

> 每个组件给"结构 / 尺寸 / 颜色引用 / 各态"。颜色一律写 token 名，不写 HEX。

### 3.1 按钮

**四种类型**：主（primary）、次（secondary）、危险（danger）、图标（icon）。三种尺寸：`lg` / `md` / `sm`。

| 尺寸 | 高度 移动 / 桌面 | 左右内边距 | 字号 | 圆角 | 用在哪 |
|---|---|---|---|---|---|
| `lg` | 48 / 44 | 24px | `--fs-body` | `--r-md` | Hero 两个按钮、登录页提交、播放页错误页按钮 |
| `md` | 44 / 40 | 18px | `--fs-sm` | `--r-md` | 卡片内按钮、留言板发布、表单保存 |
| `sm` | 36 / 32 | 12px | `--fs-xs` | `--r-sm` | 表格行内操作、提示条内"去登录" |
| `icon` | 44×44 / 36×36 | 0（居中） | 图标 20 / 18 | `--r-sm` | 全屏、关闭、抽屉开关、显示密码 |

- 移动端**任何按钮高度不低于 44px**（`lg` 48、`md` 44、`sm` 36 例外，`sm` 只允许出现在桌面或非主操作位置；触屏上 `sm` 的实际热区要用 `::after` 撑到 44×44）。
- 结构：`<button class="btn btn--primary btn--lg">文字</button>`。图标放在文字**前**，用 `<svg width="16" height="16" aria-hidden="true">`，与文字间距 `--sp-2`。**按钮文字不带箭头符号**（content-plan §9.1 已定），箭头由图标承担。
- 主按钮**一屏只能有一个**。首页 hero 的"玩我的世界"是主，其余全是次。
- 文字按钮（`btn--text`）：无底色无描边，字 `--link`，hover 下划线 `text-underline-offset:3px`。用于"查看全部""换个小游戏"。
- 危险按钮默认**不做红底**：只有"确认删除"这类不可撤销动作用 `--danger-fill`；普通危险入口用红字文字按钮。红底按钮在深色页面上非常刺眼，一屏出现两个就失控。

### 3.2 游戏卡片（首页与所有列表页共用）

**结构**

```html
<li>
  <a class="card" href="/game?id=...">
    <span class="cover cover--icon">           <!-- 或 cover--shot -->
      <img src="/default.svg" alt="" width="120" height="120" loading="lazy">
    </span>
    <span class="info">
      <span class="card-title">我的世界 1.12.2</span>
      <span class="card-desc">方块和生物最多的一版，加载也最久</span>
      <span class="card-meta">
        <span class="card-size">19.2MB</span>
        <span class="card-go">开玩</span>
      </span>
    </span>
  </a>
</li>
```

要点：整卡一个 `<a>`；`<span>` 装块级内容（`<a>` 内不能放 `<div>` 以外？——可以放 `div`，但用 `span + display:block` 更稳妥，且避免 `p` 的默认 margin 干扰）；标题**不用 h3**，因为 9 个游戏名做成 h3 会让标题层级膨胀到 3 级——那 9 个游戏名是链接文字，不是文档结构。**这一条和现有代码（`<h3>`）不同，请按此改。**

> 下表是**区块 3 / 列表页的默认档**。区块 4（Flash，每张跨 2 列）与区块 5（3 款，固定 3 列）的列数覆盖见 4.4 / 4.5，卡片内部尺寸不变。

| 项 | 移动 (<560) | 560–819 | 820–1199 | ≥1200 |
|---|---|---|---|---|
| 卡片宽 | 2 列，≈158px | 2 列，≈252px | 2 列，≈272px | 4 列，≈217px |
| 列间距 | `--sp-3` 12px | `--sp-4` 16px | `--sp-5` 20px | `--sp-5` 20px |
| 封面比例 | 16/10 | 16/10 | 16/10 | 16/10 |
| 封面高 | ≈99px | ≈157px | ≈170px | ≈136px |
| 卡片内边距 | 10px 12px 12px | 12px 14px 14px | 12px 14px 14px | 14px 16px 16px |
| 标题字号 | 14px / 600 | 15px / 600 | 16px / 600 | 17px / 600 |
| 副文案 | 11.5px→**12px**，2 行截断 | 12px，2 行 | 12px，2 行 | 12.5px→**13px**，2 行 |

- 底 `--surface-1`，边 `1px --border`，圆角 `--r-lg`，`overflow:hidden`，`--sh-1`。
- hover（**仅 `@media (hover:hover) and (pointer:fine)`**）：边 `--border-strong`、`--sh-2`、`translateY(-4px)`。触屏无 hover。
- active：`translateY(1px)`，去掉阴影——按下去的"沉"比任何动效都有效。
- 焦点：`outline:2px solid var(--focus); outline-offset:2px`（不用 `box-shadow` 画焦点环，避免被 `overflow:hidden` 裁掉）。
- 副文案 `--text-muted`，`display:-webkit-box; -webkit-line-clamp:2; overflow:hidden`。
- `card-meta` 一行两端对齐：左 `card-size`（`--font-mono` 12px `--text-muted`），右 `card-go`（12px `--link` + 右箭头 12px）。**"开玩"常显，不做 hover 才出现**——触屏上 hover 永远不会触发，那是永久性功能丢失。这是对现有实现的明确修正。
- 封面两种变体，**必须分开写**：
  - `.cover--icon`（SVG 图标，如 `default.svg`）：`img{max-width:62%;max-height:78%;object-fit:contain;filter:drop-shadow(0 6px 14px rgba(0,0,0,.5))}`，底为渐变 `linear-gradient(140deg,#1e1b4b,#312e81 55%,#4338ca)` + 两个低透明 radial。
  - `.cover--shot`（640×400 真人截图，如两款 Flash）：`img{width:100%;height:100%;object-fit:cover}`，底为 `--surface-2`。**不加 62% 限制，不加 drop-shadow**。
- `default.svg` 兜底（4 款 MC + 3 款小游戏都用它）会导致 7 张封面完全一样。补一条：当 `icon === '/default.svg'` 时，封面中央叠一行**低透明文字**——取游戏名里的版本号或数字（`1.8.8` / `1.12.2` / `2048`），24px/700，`--text-1` 透明度 `.22`。纯 CSS + 一个 data 属性即可（`.cover[data-tag]::after{content:attr(data-tag)}`），不用图片。7 张一样的封面是"未完成感"的最大来源。
- 类型徽章：**首页不显示**。理由：区块 3/4/5 已经按类型分组，徽章变成同一行里 3 个"Flash"重复 3 次，是纯噪音。徽章规格保留给播放页标题旁与 404 推荐位：高 20px，`padding:2px 8px`，`--r-xs`，11px/600，`--type-flash` 配 `--type-flash-soft` 底 + `--type-flash-border` 边。

### 3.3 导航

#### 桌面侧栏（≥820px）

- 宽 `208px`（不是 218：218 是奇数值，与 4px 网格不对齐），`position:sticky; top:0; height:100dvh`，`flex-shrink:0`。
- 底：`--sheet` 不透明（**不模糊**）。右边 `1px --border-subtle`。
- 内边距：`--sp-6 16px`（上 24 / 左右 16）。
- 结构：logo（26px 图标 + 18px/800 文字 + 11px `--text-muted` 副标）→ 分组标题（11px/600 `--text-muted`，`letter-spacing:.04em`，上下 8px）→ 导航列表 → 底部用户区（分隔线上 1px `--border-subtle`）。
- 导航项：高 44px，`padding:0 12px`，圆角 `--r-sm`，图标 18px 与文字间距 10px，字号 14px/500，字色 `--text-2`。
  - hover：底 `--surface-1`，字 `--text-1`。
  - 当前页：底 `--surface-2`，字 `--text-1`，**左侧 3px `--accent` 指示条**（`::before`，`top:10px;bottom:10px`），字重 600。
  - 焦点：`outline:2px solid var(--focus); outline-offset:-2px`（内嵌，避免被侧栏 `overflow-y:auto` 裁）。
- 6 个导航项改为真实链接 `<a href aria-current="page">`，不再用 `<button role="tab">`。侧栏内只有"游戏中心"是当前页时用 `aria-current`。

#### 移动顶栏（<820px）

- 高 `56px`，`position:sticky; top:0`，`z-index:10`。
- 底 `--sheet`（不透明，**不用模糊**）+ 下边 `1px --border-subtle`。
- 左：logo 图标 24px + `games-hub` 17px/800；中：无；右：两个 44×44 图标按钮（用户头像/登录、汉堡）。
- **打开抽屉的全屏面板**（不是下拉菜单）：
  - 从顶部推入 `translateY(-8px)+opacity` 进入，`--dur-3 --ease-out`；`position:fixed; inset:0; z-index:90`；底 `--sheet`。
  - 顶部同样的 56px 条（logo + 关闭按钮 44×44）。
  - 导航项：**高 52px**，字号 16px，左图标 20px，每项之间 `1px --border-subtle` 发丝线——抽屉里条目少，用线分隔比用间距更清楚。
  - 底部固定用户区（高 72px）：用户名 15px/600 + "退出登录" 文字按钮。
  - 打开时 `body{overflow:hidden}`；`Esc` 关闭；关闭后焦点回到汉堡按钮。
  - 抽屉打开时**不做背景模糊**（`--scrim` 用纯色 `.72` 即可），少一层合成。
- 不用"横向可滚动导航条"：6 项在 375px 宽下必然溢出，横向滚动条会藏起后 2 项，而用户不知道右边还有东西。

### 3.4 表单输入

| 项 | 值 |
|---|---|
| 高度 | 48px（移动）/ 44px（桌面） |
| 内边距 | `0 14px` |
| 字号 | `--fs-body`（15/16） |
| 圆角 | `--r-sm` 10px |
| 底 | `--field-bg` `rgba(0,0,0,.35)` |
| 描边 | `1px --border-field` `#7a76a6`（3.83:1 vs 输入框底） |
| 文字 | `--text-1`；`placeholder` 用 `--text-muted`（5.17:1，不用更淡的） |
| 标签 | 独立 `<label>`，13px/500 `--text-2`，与输入框间距 6px，**始终可见** |
| 聚焦 | 描边 `--link` + `--ring-focus`（`0 0 0 3px rgba(165,180,252,.28)`） |
| 悬停 | 描边 `--border-strong` |
| 错误 | 描边 `--danger`，下方 12px `--danger` 文字，间距 6px |
| 禁用 | 底 `--surface-1`，描边 `--border-subtle`，文字 `--text-muted`，`opacity:.6`，`cursor:not-allowed` |
| 只读 | 同禁用但 `opacity:1`，底 `--surface-1` |

**两条硬规则**：
1. **placeholder 不承担标签职责**。现有登录页只有 placeholder，输入第一个字之后"用户名"就消失了，用户回头看不出这格填什么。必须补 `<label for>`（视觉上可做小字号常驻标签，不做 placeholder 浮动标签——浮动标签需要 JS 或复杂 CSS，易出 bug）。
2. 密码框加"显示密码"图标按钮（44×44，压在框内右侧），`aria-pressed` 切换。熟人来登录，看不到自己输的字符会反复重打。

错误播报：错误文字容器 `role="alert"`（不用 `aria-live` 也行，`role="alert"` 自带 assertive）+ 输入框 `aria-invalid="true"` + `aria-describedby="field-err"`。错误文字**不要**放在按钮上方统一样式（现有 `.auth-err` 那样），要贴在对应字段下方——两个字段共用一个错误行，用户不知道是哪格错了。

### 3.6 快捷入口胶囊（区块 2）

- 结构：`<nav class="quick"><a class="pill" href="#mc">我的世界 4 个版本</a>…</nav>`，站内锚点用 `href="#id"`（不用 `onclick` 滚屏，省 JS 且可被键盘/读屏用）。
- 尺寸：高 44px（移动）/ 40px（桌面），`padding:0 16px`，`--r-pill`，字号 14px/500。
- 底 `--surface-1`，边 `1px --border`，字 `--text-1`，右侧一个 14px 下箭头图标（`--text-muted`）。
- hover：边 `--border-strong`、字 `--text-1`、图标位移 `translateY(2px)`（`--dur-2`）。
- 排列：移动 2×2（`grid-template-columns:repeat(2,1fr)`），≥560 一行 4 个（`repeat(4,1fr)`），宽度平均分配，文字超长时 `text-align:left` 不截断（这 4 条文案都在 8 字内）。

### 3.7 登录（页 + 弹窗同一套规格）

现状两处各写一套，统一为：

| 项 | 值 |
|---|---|
| 容器宽 | `min(100% - 32px, 400px)`（移动）/ 420px（桌面） |
| 内边距 | `32px 20px`（移动）/ `40px 32px`（桌面） |
| 圆角 | `--r-xl` 20px |
| 底 | `--sheet` 不透明 + `--sh-3` + `1px --border` |
| 玻璃 | **只有这一处允许** `backdrop-filter: blur(20px)`（登录页是全屏居中，只有 1 个浮层，成本可接受）；首页弹窗背后已有 `--scrim`，不需要模糊 |

自上而下顺序与节奏：

```
[品牌行]        logo 32 + games-hub 20px/800            → 下 8px
[H1]           登录后进入游戏中心  22px/700/1.3（移动 20px）→ 下 8px
[副标题]        13px/1.7 --text-2，最多 2 行             → 下 24px
[分段切换]      登录 / 注册，2 等分，高 44，圆角 10      → 下 20px
[字段 1]        标签 + 输入框 48                         → 下 14px
[字段 2]        标签 + 输入框 48 + 显示密码图标          → 下 6px
[错误行]        12px --danger，min-height 20px（占位不跳动）→ 下 8px
[主按钮]        高 48，字号 15/700                      → 下 16px
[常驻提示]      12px/1.6 --text-muted，居中              → 无
```

- 分段切换：外层 `--surface-1` 圆角 10、内边距 3px；选中项底 `--accent`、字 `--text-on-accent`、`--r-sm`，未选中透明、字 `--text-2`。**不做下划线 tab**（下划线在深色上几乎看不见）。
- **登录态提示条**（`?reason=expired`）：卡片顶部一条 `--warning-soft` 底 + `--warning-border` 边、圆角 10、内边距 12px 14px，字 13px `--warning`。这是全站唯一用黄色的地方，出现即代表"要注意"。
- 移动端**不自动聚焦**输入框（会立刻弹起键盘遮住按钮和副标题）；桌面端可用 `autofocus`。
- 弹窗版额外要求：`role="dialog" aria-modal="true" aria-labelledby`，遮罩 `--scrim`，焦点陷阱，`Esc` 关闭，背景 `inert`，关闭后焦点回到触发按钮。视觉提示"焦点被关在这里"：遮罩内卡片 `--sh-3` + 遮罩 72% 不透明（够重），不要额外加光晕。

### 3.8 空状态 / 错误状态

统一结构（**三段式，缺一段就是缺陷**）：

```
[图标 44px，--text-muted，透明度 .7]      ← 可选，纯装饰 aria-hidden
[H2 或 18px/600 标题]   发生了什么
[说明 13px/1.7 --text-2，max-width 360px]   我现在能做什么
[按钮行]   主按钮 44px + 次文字按钮
```

- 垂直内边距：移动 48px / 桌面 72px。上下居中居中，不贴边。
- 容器：如果是整页级空状态，用 `--surface-1` 面板 + `--r-lg`；如果是区块内空状态，不加底（避免"空盒子"更空）。
- 文案全部来自 content-plan §6，设计侧只负责"三段式"顺序：**标题说事、说明说因、按钮给路**。
- 断网提示条（`offline`）不是空状态：它是页顶 sticky 的一条 44px 高横幅，底 `--warning-soft`，边 `--warning-border`，字 13px `--warning`，左侧 8px 圆点。恢复时换成 `--success` 系，3 秒后淡出。

### 3.9 加载态

#### 骨架屏（只用于留言板、影视列表）

- 3 行，每行高 56px，`--r-md`，底 `--surface-1`，`margin-bottom:12px`。
- **静态，不做 shimmer 动画**。`background-position` 动画在大面积上每帧重绘，中低端安卓掉帧明显，而骨架屏只存在 0.5–1.5 秒，动起来反而像"页面在抽搐"。

## 6. 响应式策略

### 6.1 断点取值（三档，回答"820 够不够"：不够）

| 档 | 宽度 | 触发的变化 | 为什么需要它 |
|---|---|---|---|
| `xs` | <560 | 卡片 2 列（Flash 1 列）、数字条 2×2、按钮通栏或并排、页脚单列、抽屉导航 | 现有 820 一档把"手机"和"小平板"混在一起，360–430px 下的 2 列卡片必须单独定值 |
| `sm` | 560–819 | 卡片 2 列（Flash 2 列）、数字条 1 行 4 项、快捷入口 1 行 4 个、页脚仍需单列 | 横向空间到 560 才够放 4 个等宽胶囊 |
| `md` | 820–1199 | **侧栏出现**（208px）、内容内边距 24、区块间距 64、区块 6 三列、区块 7 两列、表格仍是卡片化 | 沿用现有 820 转折点（改动最小），820 是"侧栏 208 + 内容 564"的临界 |
| `lg` | ≥1200 | 卡片 4 列、区块 7 四列、内容 `max-width:1040` 居中、页脚三栏、播放页底栏出现 | 内容区需要 ≥928px 才能放 4 列 217px 的卡；1200 是"208 + 992"的临界 |

**写法要求**：新写的样式一律 **mobile-first（`min-width`）**，删掉现有的 `@media (max-width:820px)` 那一段。混用 `min-width` 和 `max-width` 是这套 CSS 后续最难维护的部分（每加一档都要回头改旧档的边界）。
**旧页面**（`/tools`、`/media`、`/guestbook`、`/account`、`/ai-admin`）本轮允许保留原 `max-width` 写法，但在抽 `assets/app.css` 时统一改掉；新 token 直接可用，不改也能跟随配色。

### 6.2 每档的布局规则

| 项 | xs | sm | md | lg |
|---|---|---|---|---|
| 导航形态 | 顶栏 56 + 全屏抽屉 | 同 xs | 左侧栏 208 sticky | 同 md |
| 内容左右内边距 | 16 | 20 | 24 | 32 |
| 内容最大宽 | 100% | 100% | 100% | 1040 |
| 卡片列数（区块 3） | 2 | 2 | 2 | 4 |
| 卡片列数（区块 4） | 1 | 2 | 2 | 2（跨 2 列） |
| 卡片列数（区块 5） | 2 | 3 | 3 | 3 |
| 区块 6 | 单列纵排 | 单列 | 三列横排 | 三列横排 |
| 区块 7 | 1 列 | 2 列 | 2 列 | 4 列 |
| H1 | 26 | 28 | 36 | 36 |
| H2（区块头） | 19 | 19 | 22 | 24 |
| 正文 | 15 | 15 | 16 | 16 |
| 区块间距 | 40 | 40 | 64 | 64 |
| 网格间距 | 12 | 16 | 20 | 20 |
| 按钮高（md） | 44 | 44 | 40 | 40 |
| 输入框高 | 48 | 48 | 44 | 44 |

> `sm` 档给 H1 一个 28px 的中间值，是因为 560–819 之间 H1 若维持 26 会显得空、跳到 36 又会换行难看。这一档只有 1 个 token 差异，成本极低。

### 6.3 移动优先的排序原则

1. **先保证"能点、能读、能滚"**，再谈视觉：任何一档下不允许出现横向滚动（`overflow-x:hidden` 是掩盖不是解决，必须在 320px 宽下逐块验证）。
2. **移动端的取舍顺序**：留卡片 → 留标题 → 留按钮 → 舍副文案 → 舍说明段 → 舍装饰。区块 3 的副标题就是按这条被砍掉的（4.1）。
3. **触屏上所有 interaction 的可用性高于 hover**：hover 只做"锦上添花"（阴影、描边），不做"功能开关"（如"开玩"文字只在 hover 出现）。
4. **sticky 只用两处**：顶栏（56px）、播放页顶栏。侧栏 `sticky` 在 md 以上才有；滚动时不允许再有第三个 sticky 元素（8 个区块的长页面，多一个 sticky 就吃掉大量可视高度）。

## 7. 性能相关的设计决策

设计侧主动关掉的东西，逐条给理由和替代方案。**这一节是设计决策，不是"建议前端优化"。**

| # | 效果 | 移动端 | 桌面端 | 理由 / 替代 |
|---|---|---|---|---|
| 1 | `background-attachment:fixed` | **完全禁止** | 改为 `::before{position:fixed;inset:0;z-index:-1}` | `fixed` 背景在 iOS Safari 上会导致每次滚动重绘整屏渐变；改用固定定位伪元素后，浏览器把它作为独立合成层，滚动不重绘 |
| 2 | 页面背景的 2 个 radial 光晕 | **关闭**（纯色 `--bg-base`） | 保留，透明度 .10 / .07 | 大面积 radial 渐变在中低端 GPU 上每帧做插值；移动端屏幕小、光晕本来也看不出来，纯色更干净 |
| 3 | `backdrop-filter` | **只允许 1 处**（移动抽屉底，可选关闭） | 只允许 3 处（侧栏、模态、Toast） | 每个模糊层都要读取背后的像素做卷积，9 张卡片 × 滚动 = 掉帧主因。视觉上深色底下"模糊"和"半透明"差别极小，用 `--surface-1/2` 就能达到 90% 的效果 |
| 4 | 卡片 `will-change:transform` | **删除** | **删除** | 9 个元素各自提升为合成层，显存和内存双重压力；只在 hover 时 `transform` 本就不需要常驻提示 |
| 5 | 卡片 `translateY(-4px)` hover | **删除**（用 `:active` 的 `translateY(1px)` 代替） | 保留，包在 `@media (hover:hover) and (pointer:fine)` 里 | 触屏没有 hover；`hover` 媒体查询同时能解决"触屏点击后 hover 粘住"的老问题 |
| 6 | 封面 `img{transform:scale(1.06)}` hover | **删除** | 保留（同一媒体查询内） | 同上。移动端封面缩放还会触发大面积的纹理重采样 |
| 7 | 骨架屏 shimmer 动画 | **删除** | **删除** | 大面积 `background-position` 动画每帧重绘；骨架屏只活 0.5–1.5 秒，静态两色块足够表达"正在加载" |
| 8 | `.counts .pill b` 渐变文字（`background-clip:text`） | **删除** | **删除** | 该属性强制单独的文本绘制路径，且 `-webkit-text-fill-color:transparent` 在部分安卓 WebView 上会把文字渲染成空白（对比度 0）。数字用 `--text-1` + `tabular-nums` 已经够醒目 |
| 9 | 全站自定义滚动条样式 | 保留（`scrollbar-width:thin`） | 保留 | 成本接近零，深色页面里默认白色滚动条很刺眼 |
| 10 | 渐变遮罩/大阴影 | 阴影降为 `--sh-1` | 按 token | 阴影在低端 GPU 上是开销项，9 张卡同时有 `--sh-2` 就要做 9 次 blur |
| 11 | `100vh` | **改 `100dvh`** | 同 | 移动端地址栏收起时 `100vh` 会让播放器底部被裁；`dvh` 是唯一正确的选择，且零成本 |
| 12 | 首屏图片 | `loading="lazy"` + 显式 `width/height` | 同 | 4 款 MC 的封面是同一个 SVG，避免为同一资源发 7 次请求（缓存会处理，但仍要显式尺寸防 CLS） |

### 7.1 `prefers-reduced-motion` 的退化

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

退化后的具体表现（设计上要保证"退化后依然可用"）：
- 卡片 hover 只有描边与阴影变化，无位移——**依然能看出"这一张是激活的"**，所以 hover 不能只靠位移表达，必须同时有描边变化（已在 3.2 定义）。
- 抽屉从"滑入"变成"直接出现"，关闭按钮位置不变——所以抽屉必须有独立的关闭按钮，不能只靠"点遮罩"。
- 进度条：不确定进度的动画条退化为静态 4px 满宽 `--accent`（避免"看起来卡住了"的误解，此时文案必须同时显示"正在下载"）。
- 滚动锚点跳转变为瞬间跳转（区块 2 的四个胶囊）——`scroll-margin-top` 仍需保留，否则顶栏会盖住标题。

## 8. 无障碍要点（前端必须满足的硬项）

### 8.1 焦点

- **全站禁止 `outline:none` 而不给替代**。当前 `.card:hover,.card:focus-visible{outline:none}` 是明确缺陷。
- 统一焦点样式：`outline:2px solid var(--focus); outline-offset:2px`；在会被 `overflow` 裁剪的容器内（侧栏、卡片）用 `outline-offset:-2px`。
- 卡片上加 `--ring-focus` 只能作为补充，不能替代 `outline`（`overflow:hidden` 会把 `box-shadow` 环裁掉一半）。
- 键盘 Tab 顺序＝视觉顺序。区块 2 的胶囊是 `<a href="#mc">`，跳转后焦点落在区块标题上（`tabindex="-1"` + `:focus{outline:none}` 但标题需要可聚焦以让读屏播报，用 `tabindex="-1"` 是标准做法）。

### 8.2 触控目标

- **最小 44×44 CSS px**（不是 24，24 是 WCAG 2.5.8 的底线，移动主力站按 Apple HIG 的 44 执行）。
- 需要额外撑热区的地方：`btn--sm`（36 高）→ `::after{content:"";position:absolute;inset:-4px 0}` 撑到 44。
- 相邻可点元素间距 ≥8px（上下排列的导航项、卡片网格的 12px 已满足）。
- 图标按钮必须有 `aria-label`，且**图标本身 `aria-hidden="true"`**。

### 8.3 对比度验收清单（逐项打勾）

| # | 检查项 | 要求 | 本文档对应值 |
|---|---|---|---|
| 1 | 正文 `--text-1` | ≥4.5:1 | 11.32:1 ✅ |
| 2 | 次要文字 `--text-2` | ≥4.5:1 | 7.75:1 ✅ |
| 3 | 12px 辅助文字 `--text-muted` | ≥4.5:1（小字不放宽） | 5.17:1 ✅ |
| 4 | 主按钮文字 `--text-on-accent` | ≥4.5:1 | 11.95:1 ✅ |
| 5 | 大字号（H1/H2 ≥19px 700） | ≥3:1 | 均 >8:1 ✅ |
| 6 | 链接 `--link` | ≥4.5:1 且**不靠颜色单独区分** | 6.46:1 ✅ + 正文链接默认带下划线 |
| 7 | 输入框描边 `--border-field` | 非文本 ≥3:1 | 3.83:1 ✅ |
| 8 | 焦点环 `--focus` | 非文本 ≥3:1 | 6.46:1 ✅ |
| 9 | 错误文字 `--danger` | ≥4.5:1 | 6.78:1 ✅ |
| 10 | 卡片描边 `--border` | 装饰性（卡片由标题文字识别），不受 3:1 约束 | 已注明 |

**底线**：任何人改色值必须重算上表第 1–9 项，并把结果写进提交说明。改 `--bg-mid` 或 `--surface-*` 的透明度**等于改了全部文字的底色**，必须整表重算。

### 8.4 弹窗焦点管理（登录弹窗 / 确认删除）

1. `role="dialog" aria-modal="true"`，`aria-labelledby` 指向标题，`aria-describedby` 指向说明（有的话）。
2. 打开时：焦点落在**第一个输入框**（桌面）或**关闭按钮**（移动，避免弹键盘）；记录打开前的 `document.activeElement`。
3. 焦点陷阱：`Tab` 在首尾元素间循环；`Shift+Tab` 反向同理。
4. `Esc` 关闭（表单有未保存内容时改为二次确认，本站在移除/删除确认框上不需要）。
5. 关闭后：焦点回到触发按钮；背景容器加 `inert`（比 `aria-hidden` 更彻底，能真正阻止点击与聚焦）。
6. 遮罩点击关闭**只在没有输入内容时**生效，避免误触清空已填内容。

### 8.5 表单错误播报

- 每个字段的错误文字容器：`role="alert"`，位于字段下方，`aria-describedby` 关联，输入框 `aria-invalid="true"`。
- 提交失败时**焦点移到第一个出错字段**，并把该字段滚入视口。
- 错误文字不用 `alert()` / `confirm()`（现有实现混用，会打断读屏且不可样式化）；删除确认用 `role="alertdialog"` 的模态框。
- 成功提示用 `role="status"`（polite），不要用 `alert`（会打断用户正在做的事）。

### 8.6 语义与结构

1. 每页**只有一个 H1**。首页 H1 是"9 款游戏，打开就能玩"；`view-ai` 里的 H1 必须改成 H2。
2. 导航是 `<nav aria-label="站点导航">` + `<a aria-current="page">`，**不是 `role="tablist"`**。
3. 游戏列表是 `<ul role="list">` + `<li>` + `<a>`，`role="list"` 显式写回是因为 `list-style:none` 在 Safari 上会移除列表语义。
4. `html{color-scheme:dark}`：让原生控件（滚动条、自动填充背景、日期选择器）跟随深色，否则 Chrome 自动填充会把输入框刷成白色。
5. 图片：装饰性封面 `alt=""`（标题已在文字里，避免读屏重复念游戏名）；Flash 截图若是唯一信息载体才写 `alt`。所有 `<img>` 必须有 `width`/`height`。
6. `lang="zh-CN"` 保留；英文单词（Ruffle、Flash、H5）不需要额外标注。
7. 抽屉打开时 `body{overflow:hidden}` + 主内容 `inert`；关闭后恢复。

## 10. 收尾三行

**这套规范的关键取舍**
放弃"每张卡都毛玻璃"的饱和度，换来移动端稳定 60fps 和一套能锁死对比度数值的表面 token；放弃筛选 tab，换来 8 个区块各自说清"这是什么"——代价是用户失去"只看 Flash"的快捷路径，用区块 2 的胶囊补上。

**前端最容易做走样的 3 个点**
1. **封面两种变体混写**：把 640×400 的 Flash 截图套上 `max-width:62%` 的图标规则，变成一张小图贴在渐变中间；或者把 SVG 图标套上 `object-fit:cover` 拉变形。必须按 `.cover--icon` / `.cover--shot` 分开写。
2. **移动端留了 hover 才算完**：`translateY(-4px)`、`img{scale(1.06)}`、"开玩"文字显隐都必须包在 `@media (hover:hover) and (pointer:fine)` 里，或干脆常显。触屏上 hover 是不存在的，写成 `:hover` 就是永久功能丢失。
3. **对比度被"调色"击穿**：只要有人把 `--surface-1` 的透明度从 `.06` 提到 `.10`，或把 `--bg-mid` 提亮，`--text-muted` 就会从 5.17:1 掉到 4.55:1 以下。**改底色 = 改全部文字对比度，必须重算第 8.3 节整张表。**

**需要你拍板的 1–2 个决策**
1. **移动端导航要抽屉还是底部 Tab 栏？** 我按"顶部 56px + 全屏抽屉"设计（理由是 6 个入口超出一个 Tab 栏的容量，且长页面里底部栏会永久吃掉 56px 可视高度）。但底部 Tab 更符合"拇指可达"，且切换更快——如果你更看重切换效率，我改底部 4 项（游戏中心 / 工具箱 / 留言板 / 我的），AI 助手挪进"我的"里。
2. **只做深色单主题，还是要跟随系统浅色？** 我建议**只做深色**（`color-scheme:dark`），理由是游戏画面本身是黑的、浅色版会让"加载中"闪白。代价是白天强光下屏幕可读性差。如果你要求浅色，我需要重排一套亮色 token——那是另一份工作量，不是加个 `@media` 能解决的。
